## CRITICAL findings

### C1. Cover counts strict sign patterns for a fixed scale problem

For a fixed channel ordering, let row (j) of (G) consist of the channelwise dot products before multiplying by the target sign. The candidate signs are the strict homogeneous dichotomies of the (n) rows in `C` dimensions as the real scale vector varies. Cover's formula counts them in general position and gives an upper bound for the number of strict patterns in degenerate cases. The positive simplex and the scale floor restrict that family further. Dividing the count by (2^n) gives a probability bound for a uniform independent target on fixed rows. A separate idealized construction can instead assume independent symmetric row orientations with a fixed target and account for ties. A deterministic Reed–Solomon encoding of a manifest digest has at most (2^{256}) possible words, so uniformity over the ambient (2^n) labels cannot be inferred from hashing. The keyed matrix is derived deterministically using SHA-256 and SHAKE-256. State the cryptographic randomness assumption and what is fixed independently of the key. [Cover's original paper](https://doi.org/10.1109/PGEC.1965.264137).

The formula evaluates to `log2 P = −239.7089` for (512, 64), `−139.8589` for (384, 64), and `−1` for (32, 16). This verifies the arithmetic in `paper1/method.tex:53–57` and the fixed-order eligibility calculation in `embedding/align.py:90–106`. It does not establish the manuscript's security claim. `embedding/align.py:109–130` yields up to four views: raw, target-scored permutation, scaling, and normalized-block target-scored permutation followed by scaling. The optimization selects assignments using the expected codeword. Counting only the candidates returned would omit the assignments considered by the optimizer. The same code yields LP candidates when the solver succeeds even if the optimized margin is nonpositive. `verify/verify_model.py:129–153` then tries error-correcting decode and accepts payload equality. This event includes inputs whose raw signs disagree with the target within a decoder-dependent region. A bound for strict sign fitting, even for pure scaling, does not bound that acceptance event. A proof for the complete verifier would have to account for target-dependent assignment, the full decoder and its acceptance regions, tie conventions, configuration selection and the adversary's trial budget.

The linear assignment exactly maximizes the summed signed-logit objective in Eq. (5). SciPy documents a modified Jonker–Volgenant solver for the routine called by the code. Kuhn is historical context. The objective does not optimize the minimum margin or ensure that the maximizing assignment is the original order. The combined normalized pass is a heuristic. For the LP, the code rescales its constraint matrix for numerical conditioning, uses 64 scale variables plus margin, and has (n) margin inequalities, one normalization equality and 64 lower bounds. Inversion with the true factors is only feasible if the normalized factors clear the floor. Strict recovery further requires appropriate clean margins and numerics. `tests/test_phase6b.py:136–159` checks constructed examples and gate cases. `tests/test_phase6_attacks.py:35–65` uses numerical tolerances for function preservation. In eval mode, paired channel permutations and compensated positive scaling admit the algebraic argument through positive-homogeneous ReLU and max pooling. Output-side rescaling in `attacks/weight_attacks.py:96–115` also traverses BatchNorm with epsilon, so its observed accuracy agreement is approximate. [SciPy solver documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html).

**Required fix.** Rename the bound as a conditional fixed-order strict sign-fit bound everywhere, including the abstract, Fig. 1, Fig. 8, Table I, README and threat model. Separate it from the heuristic eligibility gate and observed recovery. Either supply a theorem for the implemented acceptance event with a stated null and adversary or omit the end-to-end probability claim. Report recovery under the sampled edits, including which candidates and erasure counts passed.

### C2. The residual threshold has a valid calculation and a conditional interpretation

With fixed target, configuration and checkpoint independent of newly sampled ideal row signs, independent fair nonzero projection signs give `Binomial(n, 1/2)` agreement. Symmetry alone does not give independence. The implementation reuses a fixed secret key and release and applies a deterministic SHAKE expansion. Related weights, known marks, verifier feedback, repeated submissions, configurable extraction and attacker-selected checkpoints fall outside the one-shot derivation. Random-key controls, fixed-key random models and genuine unrelated trained models measure different populations. Zero logits also matter. `embedding/align.py:149–152` treats a zero logit as bit 0, while `paper1/method.tex:58` excludes zeros for either sign via a strict product. Explicitly handle ties in the null and in the formula.

Integer binomial sums give `358/512` with `log2 tail = −64.1921` and `357/512` with `−62.9745`. For RS16 the cutoff is `280/384` with `−64.2083`, while 279 gives `−62.7822`. This is a size threshold under the stated null for a raw score computed before alignment. DAMAGED is a subset of the raw threshold event because exact success has precedence. The tail is neither an estimate for the whole verifier nor a probability that the checkpoint has the claimed origin. If 778 tests had been independent draws from one common Bernoulli population, zero events would give a one-sided 95% upper limit of about 0.384%. Here the mixed clustered controls do not justify applying that limit to a general attacker population.

**Required fix.** Describe DAMAGED as residual statistical evidence under explicit assumptions. Specify the auditor's fixed settings, key regime, tie rule and submission budget. Label the 53-position distance in Fig. 7 as an observed distance, replacing “53-bit safety gap.” Report the RS16 cutoff separately. Extend validation to marked and unrelated models across independently sampled keys and manifests, keeping adaptive evaluation separate.

### C3. Specify what the verifier and attacker control

`verify/verify_release.py:19–61` checks the signature, algorithm, public key identifier and `payload.hex`. `verify/verify_model.py:44–61,83–153,175–205` loads the signed architecture/width, verifies count and finiteness, then uses unsigned ECC, layer and mode chosen by CLI, adjacent `final.json`, or defaults. The full-length guard matches the signed length and supports legacy mode through `--allow-short`. Therefore the 256-bit RS/mean-mode claim describes a pinned profile. The published entry point does not enforce that profile universally. `embedding/extract.py:11–22` uses restricted PyTorch loading on supported versions but retries with default loading after a `TypeError`. Pin and test loader behavior before claiming that no arbitrary pickle is executed for every supported environment. The manifest authenticates a key holder's statements. Its key ID is a consistency check and depends on an independently trusted public key.

The experimental remover has weights and uses fixed, largely key-blind configurations. The same-layer overwrite knows the carrier and independently embeds another mark, using a 20% CIFAR-10 subset. It does not measure an attacker who gets the original watermark key, receives repeated verifier feedback, chooses extraction settings or tries multiple manifests. `docs/threat_model.md:49–65` records dummy-neuron rejection and shared development signing keys. Function-preserving changes that violate signed shape may be rejected by construction. The project’s useful-rejection definition classifies that outcome as removal if accuracy stays within budget. Distillation, operation through a prediction API, cross-layer overwrite, larger structural edits, transfer and longer tuning remain untested. Phase 5 negative-case tests cover sample tampering and mismatched inputs. They do not prove cryptographic unforgeability or ownership adjudication.

The signed dataset root binds the reported ordered byte sequence under the hash assumptions, and the optional release dataset check compares a supplied CIFAR-10 copy. The main model verifier does not recompute that root. Train loaders augment inputs separately and training accepts a payload file. A valid mark does not establish the training history, exclusive data use, pre-signing cleanliness, consent, legal ownership or priority. `created_utc` is self-declared. Independent timestamping can establish a time assertion for a record under its own trust assumptions. Public verification or zero knowledge would change the trust model and remains a design option. [RFC 3161](https://www.rfc-editor.org/rfc/rfc3161).

**Required fix.** Define the verification profile, trust anchor, model access, attacker information, attacker budget and operational key custody. Separate development keys from release credentials, publish a disposable research release or arrange controlled research-key access, and document ownership disputes and dataset checking as separate protocols. Scope “post-quantum” to the external ML-DSA signature under its assumptions. The watermark does not inherit ML-DSA security. Treat the README's “proof inside the weights” and “provably derived” as claims requiring revision.

## IMPORTANT findings

1. **Define the unit of replication.** In each design the 252 rows are 84 evaluations for each of three trained models. The registry defines 47 modifications plus one clean configuration, with 18 triplicated and 30 single-run configurations per seed. The same weights, key, release digest and test set are reused. Attack seeds are generated from source, training seed, ID and repeat. They are paired across marked designs for identical source labels and are not new trained models. At 512 bits there is one attacker draw per parent. The comparison has five clean seed pairs and three robustness pairs. Report paired raw results, cluster by parent and independent key/release when enough are available, and avoid model-level inference using 252 as the sample size. Five positive hinge differences are descriptive evidence. An exact two-sided sign test with independent pairs gives (2/32 = 0.0625). Zero of three or three of three overwrite outcomes give wide rate intervals even under an independent common-rate model.
2. **Preserve the narrow mechanism.** BCE supplies a nonzero per-bit derivative at finite margins in exact arithmetic and hinge's implemented ReLU gives zero watermark gradient at and above its margin. The projection gradient affects the shared direction because the carrier is the mean. Total task gradients and weight decay persist. The carrier decomposition and pooled logits establish an association. They do not isolate causation through the shared norm or prove residual filters lost discriminative capacity. Define shared energy as `128 × squared norm of v / squared Frobenius norm of W`, define own norm as an average of per-filter residual norms, show run-level values and distinguish pooled from per-seed summaries. Add matched embedding-strength and pre-overwrite margin comparisons, including the single `m=2.5` run as exploratory. Measure attacker bit error rates as well as victim verdicts. The tested overwrite uses identical setting values across designs, while attacker BER differs across them.
3. **Improve the baseline comparison.** Naive single-weight signs are stamped onto already trained weights with no task retraining. Projection is trained jointly and has a target-dependent alignment stage. The evaluation uses two versus three seeds, one versus three stochastic draws, different attack randomness namespaces, and omits training attacks on the naive side. Keep the practical pipeline comparison as exploratory. Match seed, draws, attack budgets, utility, payload and verifier assumptions, and add projection with alignment disabled and matched no-ECC controls. RS16 and RS32 use the same 256 payload bits and different redundancy, projection dimensions and codewords. A comparison at the same `λ` does not isolate the effect of parity count.
4. **Publish a reproducible run manifest.** Pin code, dependencies, CUDA/T4 runtime, seed and data split, signed release inputs, weight hashes, attack seed tuples, verifier settings and revision, decoder mode, figure source and commands. `requirements.txt` uses lower bounds and leaves liboqs installation separate. The figure script imports seaborn, which is absent from that requirements file. The notebooks require a matching watermark-key fingerprint. Use an archive with a disposable research key or a controlled independent reproduction. Validate `attacks/evaluate_attacked.py:34–51` used the correct per-design clean probe for the saved rates. Store direct raw agreement, raw bit disagreement against the signed target, byte errors, correction count, erasures and candidate selected. `attacks/measure.py:81–107` currently defines `flip_rate` relative to clean signs via NumPy, so it is a surrogate for target agreement even on the selected clean zero-error runs if attacked zeros occur. Generate tables and annotations from the rows rather than fixed prose.
5. **Qualify the decoder evidence.** For shortened systematic RS over GF(256), bounded-distance decoding can correct (e) unknown erroneous bytes and (f) known erasures when (2e+f\le r). A confidence ordering neither identifies all erroneous bytes nor guarantees recovery outside that decoding region. `embedding/ecc.py:93–114` tries first-success decode, erasing an even number of least-confident bytes up to (r/2). Decoder success and matching the signed digest are different outcomes. In the published 3-bit BCE/RS32 rows, the mean of 5.33 bytes repaired is supported, and **all three rows have zero erasures**. Ordinary hard RS sufficed in this example. The 1,000/1,000 uncapped and 0/1,000 capped Gaussian claims trace to `docs/results_log.md:48–50` without a linked complete result artifact. An independent in-memory check used NumPy RNG seed 3, 1,000 vectors of 512 standard-normal logits and reedsolo 1.7.0. It produced 0/1,000 capped decoder successes and 1,000/1,000 when all 32 least-confident positions were supplied as erasures. This checks decoder return behavior on fresh inputs. Save code, seeds, exact distribution/shape, decoder versions and separate wrong-payload versus exact-match counts. Distinguish remaining parity budget from a false-accept guarantee.
6. **Resolve LaTeX layout issues.** A scratch build with pdfLaTeX, BibTeX and the IEEEtran class produced a nine-page letter PDF. The final log reports overfull boxes for the Cover equation by 1.28 pt (`paper1/method.tex:56`), and for the clean accuracy, weight decomposition, robustness and false-positive tables by 2.66, 49.01, 64.88 and 21.09 pt (`paper1/evaluation.tex:17–31,50–60,75–84,106–121`). Resize or rework the tables for the target column widths, then review the final render against the target venue’s page limit and submission rules.
7. **Validate references against primary material.** Use the bibliography inventory in the matrix. Distinguish pre-standard Dilithium3 from ML-DSA-65, an external attestation schema from a dataset commitment, and media watermarks from model-weight watermarks. Attribute published comparisons to each study's settings. The prototype contribution is the integration and measured tradeoff. A first-of-kind or comprehensive novelty claim requires a wider related-work search, including robust white-box extraction and ownership-ambiguity studies.
